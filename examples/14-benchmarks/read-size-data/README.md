# Read-only comparison evidence

See [the report](../READ-SIZE-2026-09-25.md). `comparison/` contains the primary
four-way run; `mixed-upload/` contains the sequential directional fairness check.
Source snapshots derive from 5c960b2 and the two top-level patches. They were
never applied to the local runtime. No duplicate source/test trees are included.

Recreate summaries from the repository root (replace PHASE with smoke or timed):

```sh
python3 examples/14-benchmarks/read-size-data/comparison/summarize.py examples/14-benchmarks/read-size-data/comparison PHASE
python3 examples/14-benchmarks/read-size-data/mixed-upload/summarize.py examples/14-benchmarks/read-size-data/mixed-upload PHASE
```

The scripts rewrite their JSON summaries. Benchmark driver paths identify the
original AWS layout and must be adapted for another host. The mixed-upload
runner points to the same immutable source directories used by the primary run.
Each POST payload is regenerated by the harness (1 MiB of x for large/mixed
uploads, 1 KiB for the small POST smoke). Mutable post-payload.bin files are
excluded so a final small-body file cannot misrepresent earlier commands.
Raw logs are preserved verbatim. Metadata plus per-run command/case settings
identify the workload; smoke uses one read64 run per case, while timed runs
compare all four variants. Background and bulk windows differ; do not sum
rates or pool percentiles. Both runtime patches retain default autoflush.

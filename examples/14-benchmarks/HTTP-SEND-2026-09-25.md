# Two HTTP performance experiments — shared send retained

## Decision

Retain the shared HTTP send coroutine on `experiment/http-simplification`.
Discard the combined header scan. Both
prototypes were independently based on `efbed54`, whose runtime is the retained
`874b120` checkpoint; they were never layered together. No new branch, public
API, option, cache or event-loop workaround was introduced.

Shared send improves ordinary GET, ten-header GET and POST by 4.5–5.1% over the
saved checkpoint, positive in every round. Streaming is effectively flat in
these samples. The header scan has no persuasive overall benefit: GET -1.68%,
ten-header GET +0.17%, POST +0.99%, streaming +0.06%. Its patch is evidence only.

## What changed

`_create_send` now returns a small ordinary closure that delegates to the named
`_send_http_event` coroutine. The coroutine body is shared across requests; the
existing captured fields live in one private per-send hash. Sequencing,
publication, file/fh/trailer rollback, framing, backpressure and terminal
notification remain in their original order. The connection stays weakly held,
including across a suspended send. HTTP/2 and accepted SSE/WebSocket send paths
were not hoisted.

This exchanges per-request async closure setup for nine private hash fields and
one forwarding call. It is a measured tradeoff, not a reduction in every kind of
work. The previous rejected scalar-alias ownership experiment is not included;
there is no new keep-alive detachment rule.

The discarded header probe merely combines Content-Length, Date and Upgrade
field discovery after validation and stripping, without changing header order
or duplicates. Fewer scans did not produce a useful measured improvement.

## Native AWS comparison

Standalone c7a.xlarge, Perl 5.42.2, IO::Async::Loop::EV 0.05, pure-Perl Future,
epoll. Server on CPU 0, driver/telemetry on CPU 1, clients on CPUs 2–3. One
worker, 25 HTTP clients, 20 persistent WebSocket clients. Same installed CPAN
release and benchmark apps for all variants; no profiling or dependency changes.

Three ten-second samples per HTTP variant and two per SSE/WebSocket variant.
Orders: release/saved/headers/send, send/headers/saved/release, then
saved/release/send/headers. Controls use the first two orders. HTTP has the
harness's one-second warmup and correctness preflight, including split-body
POST. These results are not pooled with earlier runs.

Shared-send changes against saved, paired by round:

- GET: +4.60%, +5.70%, +3.26%.
- Ten-header GET: +3.51%, +4.83%, +5.60%.
- POST observer: +5.22%, +6.34%, +3.75%.
- Chunked stream observer: -0.39%, -1.29%, +0.78%.
- SSE: +0.68%, +2.84%.
- WebSocket: -0.78%, +1.28%.

The consistent HTTP gains justify retaining shared send. Streaming directions
are mixed and small. Accepted SSE and WebSocket use separate send paths, so
these control differences are not evidence of a speedup from this change.
WebSocket may be client-limited. Short samples on a shared server/client host do
not establish universal throughput or exact percentage effects.

All **24 smoke runs and 64 timed runs passed**. Timed runs returned 2,688,255
HTTP responses and checked 994,550 WebSocket echoes. Source and loaded dependency
hashes stayed unchanged. All 744 interval vmstat samples reported zero swap-in,
swap-out and steal; I/O wait peaked at 2%. Raw client logs, process resources,
telemetry, identities and all samples are retained; none were discarded.

## Correctness and review

Header checks: 5 files / 55 tests passed. Shared-send focused checks: 17 files /
230 tests passed, covering validation, headers, backpressure, cancellation,
refusals, rollback and terminal ordering. The three-subtest lifetime regression
passes against the original and candidate runtimes, and against the candidate
on Linux. It covers a saved send across keep-alive reuse, a retained send after
owner destruction, and a send suspended on backpressure while its owner dies.

Removing weakening from the shared coroutine is a failing negative control:
the connection stays alive and the parked send does not settle as expected.
A separate attempted control leaving the invocant in `@_` did **not** fail;
it provides no regression evidence. Both logs are preserved.

The full enabled local suite passed: **180 files / 1,273 tests**, including
HTTP/2, in 1,098 seconds. Opt-in release/stress tests and gated cross-distribution
integration tests remain skipped as configured. These local timings are not
performance data. The runtime under test exactly matches the benchmarked
shared-send source; `t/http-send-lifetime.t` adds the lifetime checks.

```sh
perlbrew exec --with perl-5.42.2@default env PERL_FUTURE_NO_XS=1 prove -lr t
```

Independent read-only review found no blocking correctness issue. Normalizing
the coroutine gives the original body with scalar-to-hash substitutions. One
incidental difference exists after the owner has disappeared: the wrapper
returns a completed Future directly rather than through an async closure. The
successful no-op contract is preserved; the incidental resolved result payload
is not treated as public API. See `last-two-data/review.md`.
